# 08. 嗜好抽出パイプライン

会話テキストからユーザーの嗜好を構造化抽出し、`preference_profiles` に蓄積する。`get_user_profile` ツールで嗜好データを提供する。

設計: [docs/設計/レコメンデーション/README.md](../設計/レコメンデーション/README.md)

## 08.1 DB スキーマ ✅

### 08.1.1 preference_profiles テーブル・インデックス作成 ✅

- `postgresql/init/005_personalization.sql` を新規作成
- `preference_profiles` テーブル（id, bank_id, entity_id, category, item, sentiment, intensity, context, source_memory_ids, evidence_count, first_mentioned_at, last_mentioned_at, created_at, updated_at）
- UNIQUE 制約: `(bank_id, entity_id, category, item)`
- インデックス: `(bank_id, entity_id)`, `(bank_id, entity_id, category)`
- `pg_trgm` 拡張を有効化（item 名寄せに必要）
- CHECK 制約: category, sentiment, intensity の値制約を追加

### 08.1.2 banks テーブル拡張 ✅

- `banks` テーブルに `owner_entity_id` カラム追加
- `ALTER TABLE banks ADD COLUMN IF NOT EXISTS owner_entity_id UUID REFERENCES entities(id)`

## 08.3 嗜好抽出モジュール ✅

### 08.3.1 嗜好分類 LLM 呼び出し ✅

- `recommendation/src/recommendation/preference_extractor.py` を新規作成
- Claude 3 Haiku で会話テキストから嗜好を構造化抽出
- 設計書 4.3 節のプロンプトを使用
- 出力: JSON 配列 `[{category, item, sentiment, intensity}]`
- 嗜好シグナルがない場合は空配列を返す

### 08.3.2 エンティティ特定 ✅

- Phase 1 では `banks.owner_entity_id` のみ使用（並列実行のため Fact の who 情報は未生成）
- `owner_entity_id` が未設定の場合はスキップ
- `get_owner_entity()` を `preference_query.py` に集約

### 08.3.3 item 名寄せ ✅

- UPSERT 前に `pg_trgm similarity` で既存レコードとの類似度チェック
- クロスカテゴリ名寄せ（閾値 0.8）→ 同一カテゴリ内名寄せ（閾値 0.6）の順で実行
- 一致すれば既存のカテゴリ・item 名を採用
- WHERE 句に `similarity(item, $1) >= $N` を追加し GIN インデックス最適化

### 08.3.4 UPSERT ロジック ✅

- 新規: LLM 出力の値をそのまま INSERT
- 再言及（同一 sentiment）: intensity を指数移動平均で更新 `new = old * 0.7 + extracted * 0.3`
- sentiment 変化: 新しい sentiment で上書き
- `evidence_count` をインクリメント
- SAVEPOINT（ネストトランザクション）で個別 UPSERT 失敗を分離
- `source_memory_ids` は Phase 1 では空配列（並列実行のため）
